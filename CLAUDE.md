# CLAUDE.md — Catenna

Персональная операционная система жизни (Flutter, Android в первую очередь; дальше Desktop и Web).
Структура проекта, хранилище и функциональность описаны в `README.md`. Здесь собраны принципы и правила работы.

## Концепция (коротко)
- Три измерения жизни: **BODY** (`body`), **MIND** (`mind`), **MATERIAL** (`material`). Это измерения
  одной жизни, а не три отдельных приложения. Событие или цель может затрагивать несколько измерений.
- Модель строится вокруг **процессов, событий, целей и ресурсов**, а не вокруг трекеров.
  Ядро — журнал событий `LifeEvent` (`lib/models/life_event.dart`). Процессы `LifeProcess`
  (`lib/models/life_process.dart`) — рамки для событий: их числа всегда выводятся из событий, а не хранятся.
- Ресурсы: время, деньги, энергия (субъективная шкала 1–5), внимание. Система показывает, куда они уходят.
- Три времени: PAST (история), PRESENT (текущее состояние), FUTURE (цели).

## Принципы продукта — проверяйте каждое изменение
- **Evidence-based.** Только данные пользователя или источников (Health Connect). Никаких выдуманных показателей.
- **Historical integrity.** История не переписывается: правка = новая версия (`supersedesId`), отмена = пометка
  (`voidedAt`). Физическое удаление — только явное действие пользователя с подтверждением. Старые записи журнала
  событий не вытесняются по пределу.
- **No false precision.** Не сводить жизнь к одному индексу. Оценки (восстановление мышц) называть оценками и округлять. Не усреднять субъективные шкалы. «Не указано» (null) ≠ 0.
  Если данных недостаточно, так и показывать: «указано в 2 из 5».
- **Transparency.** Видно происхождение данных (`source`) и время записи (`recordedAt`) рядом со временем события (`at`).
- **User ownership.** Локальное хранение, шифрование, экспорт и импорт. Ничего не отправлять наружу.
- **Не решать за человека.** Давать информацию и контекст, а не оценки и предписания.
- **Minimalism.** Минимум интерфейсного шума.

## Правила кода
- UI не меняет данные напрямую — только через методы `AppController` (`lib/state/app_controller.dart`).
  Доменные операции — расширения в `lib/state/ops/*.dart` (`part of` контроллера); новую область — туда же, не в класс.
- Любое изменение данных — только внутри `_commit(...)`: он пересчитывает производное (`_syncDerived`) и сбрасывает
  кэш `_memo`. Изменение в обход `_commit` оставит на экранах устаревшие данные. Тяжёлое производное (по всему журналу),
  которое экраны читают при перерисовке, — геттером контроллера через `_memo`, а не расчётом в виджете.
- Новый необязательный блок интерфейса — в реестр `Sections` (`lib/core/sections.dart`) и под `c.isShown(...)`.
- Логика без Flutter → `lib/core/`, модели → `lib/models/`, экран → `lib/ui/screens/`, переиспользуемый блок → `lib/ui/widgets/`.
- Название приложения — **Catenna** (лат. «цепь»: дни и события одной жизни). Внутренние имена остаются `lifeos`:
  идентификатор, пакет `life_os`, формат копий `lifeos-backup` и файлы `*.lifeos`, секреты `LIFEOS_KEYSTORE_*` — их смена
  ломает обновление поверх, восстановление старых копий или подпись.
- Android-проект — в репозитории (`android/`, `docs/RELEASE.md`). Идентификатор `io.github.yrgez.lifeos` не менять
  (иначе обновление не встанет поверх). Новое разрешение или нативная настройка — в манифест/Gradle и в
  `test/android_project_test.dart`. Разрешения INTERNET нет и не будет. Движок отрисовки — Skia (Impeller портит текст
  на Galaxy S10), поэтому Flutter в CI закреплён (3.50.0); обновлять — по `docs/RELEASE.md`.
- Плагины — только за интерфейсами (`AppRepository`, `HealthDataSource`, `FileSource`, `BackupStorage`, `ReminderScheduler`, файлы `*_authenticator`, `secure_key_store`, `sqlcipher_opener`).
- Смена формата JSON → поднять `kSchemaVersion` (`lib/data/app_data.dart`). Смена таблиц → поднять `kDbVersion` и добавить шаг
  в `onUpgradeSchema` (`lib/data/sqlite_app_repository.dart`). Новую таблицу добавить в `SqliteAppRepository.tables`
  (иначе миграция шифрования откажет).
- Любая мутация журнала (подходы, операции, события, дневные снимки) обязана попасть в `_pending` (`ChangeSet`),
  иначе упадёт `storage_sync_test`. Снимок текущего дня обновляет `_touchToday` (из `_syncDerived`), прошлые дни — только источник данных.
- Импорт копии (`strict: true`) отвергает любую битую запись. Обычная загрузка терпима, но ничего не «чинит» молча.
- Тексты интерфейса и комментарии — на русском.
- Деньги в интерфейсе — только через `fmtCur` / `cur` (`lib/core/currency.dart`), не символ «₽» в строках.
- Дизайн: плитки — `tileDecoration()` / радиусы `AppRadii` (только токены), размеры шрифта — только шкала `AppText.scale`
  (11 / 13 / 16 / 22 / 34), заголовок секции — `AppText.caption`; это проверяет `test/design_tokens_test.dart`.
  Текст — `AppColors.text` / `AppColors.muted`, главное действие
  белое (`AppColors.accent`). Цвет только со смыслом (измерения, доход/расход), не для украшения; предупреждение — текстом (белым), а не цветом.
  Измерения — `AppColors.body` / `mind` / `material`: на круге Иттена синий и расщеплённый дополнительный оранжевый
  (тёплое — тело, холодное — разум, охра — материальное; они же на значке). Оттенки внутри измерения — ступени светлоты того же тона (восстановление мышц),
  у категорий денег — охра. `green` / `red` — только «плюс / минус» (доход и расход, рост и падение); серые — нейтральные, без синевы.
- Графики: заливки измерений — `dimensionChartColor` (проверены на тёмной поверхности), не яркие `dimensionColor`.
  Значения всегда подписаны текстом: измерение не различается только цветом.
- Доступность (`test/accessibility_test.dart`): нарисованный график — в `ChartSemantics` с данными из `describeSeries`
  (`lib/core/chart_text.dart`); нажимаемое на холсте — узлами `semanticsBuilder` художника. У кнопки-иконки — `tooltip`;
  область нажатия не меньше 48 px (переключатели — `SegmentPill`). Цвет текста — из палитры с контрастом ≥ 4.5:1. Плитки в ряд — `AdaptivePair` (при шрифте ≥ 130 % встают друг под другом),
  строка «текст — значение» — `LeadTrailing`, переключатель — `adaptiveSwitchTile`. Новый экран или диалог — в
  `test/large_text_test.dart`: он ловит переполнения и слова, разорванные переносом, на всех шагах шрифта Android.

## Проверка
```
flutter pub get && flutter analyze --no-fatal-infos && flutter test
```
Тесты SQLite используют `sqflite_common_ffi` и системную `libsqlite3`. CI: `.github/workflows/ci.yml`.
В облачной сессии Flutter заранее не установлен — поставить ту же версию, что в CI, до любой проверки:
```
git clone -q --depth 1 --branch 3.50.0 https://github.com/flutter/flutter.git /opt/flutter
ln -sf /opt/flutter/bin/flutter /usr/local/bin/flutter && ln -sf /opt/flutter/bin/dart /usr/local/bin/dart
```

## Инструменты агента (`.claude/`)
- Плагины **ponytail** и **Dart and Flutter** встроены в репозиторий, а не ставятся через `/plugin`: облачные сессии
  плагины из сторонних каталогов не ставят. ponytail — хуки `.claude/hooks/ponytail-*.js` (в `.claude/settings.json`)
  и навыки `.claude/skills/ponytail*`; Dart and Flutter — навыки `.claude/skills/dart-*`, `flutter-*` и Dart MCP server
  в `.mcp.json` (стартует, только если Flutter установлен до начала сессии). Устанавливать их ещё и через `/plugin`
  не нужно — будет двойная загрузка. Обновление — `.claude/hooks/PONYTAIL.md`, `.claude/skills/DART-FLUTTER.md`.
- Правила этого файла главнее советов плагинов: архитектура — `AppController`/`ChangeNotifier` (не BLoC/Riverpod),
  ширина строки 160 (`dart format -l 160` переформатирует чужие строки — не применять к целому файлу).

## Ветки и PR
- PR вливается **только обычным merge** — не squash и не rebase: номер сборки (versionCode) = число коммитов в истории.
  Если он уменьшится, Android не поставит сборку поверх установленной, и придётся удалять приложение вместе с данными.
  Пробные сборки с ветки (workflow_dispatch) тоже ставятся на телефон — их коммиты из истории не убирать.
- Проверка на телефоне — Galaxy S10 (Exynos, Mali-G76): пробную сборку собирает CI на ветке, APK — в артефактах запуска.
- PR, созданный агентом по просьбе владельца, агент сразу берёт под наблюдение (`subscribe_pr_activity`): отвечает на ревью
  и чинит упавший CI до слияния, не спрашивая отдельно.

## План развития (каждый шаг — отдельный PR)
1. ✅ Журнал событий `LifeEvent`: измерения, ресурсы, версии, связи с целями, хранение, экран.
2. ✅ Процессы (`LifeProcess`): длительные процессы, журнал статусов, ресурсы считаются из событий.
3. ✅ Ресурсы: распределение времени, денег и энергии по измерениям и процессам за период.
4. ✅ Хроника (PAST): лента событий, ежедневные снимки состояния вместо затираемых недельных массивов.
5. ✅ Цели (FUTURE): план ресурсов ↔ факт из событий (напрямую и через процессы цели).
6. ✅ Против ложной точности: `systemReadiness` → «восстановлено N из M», без r по 7 точкам, цели «2 из 5»;
   узлы графа связаны с процессами и целями (`NodeRef`).
7. ✅ Навигация: Сегодня / Тело / Разум / Материальное / Хроника; узкий экран (360 px) проверяется тестом.
8. ✅ Осмысление: обзор недели, «В этот день»; быстрая запись; одна правда о деньгах (счета), история целей;
   сон и вес из Health Connect; открытый экспорт (CSV, Markdown); эксперименты «до/после» и ресурс «внимание».
9. ✅ По аудиту слабых сторон: автокопия в выбранную папку, локальные напоминания, свои категории и правила разбора
   выписки, поиск, задачи (намерение → «Сделано» = событие журнала), доступность (TalkBack, русские системные тексты,
   области нажатия 48 px, крупный шрифт до 200 %).
10. ✅ Сборка для установки: Android-проект в репозитории, постоянный идентификатор, подпись своим ключом,
   номер сборки из истории, выпуск по тегу; release-сборка без разрешения INTERNET.
