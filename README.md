# Life OS — структура проекта

```
lib/
  main.dart                    точка входа: перехват ошибок, SQLite-хранилище, источник Health Connect
  app.dart                     MaterialApp
  core/                        чистая логика без Flutter-состояния
    utils, workout_stats, finance_stats, finance_categories, graph_stats, theme, app_log
  models/models.dart           модели данных + JSON
  data/
    app_data.dart              AppData — весь сохраняемый срез состояния
    app_repository.dart        интерфейс AppRepository, PrefsAppRepository (прежнее хранилище), MemoryAppRepository
    sqlite_app_repository.dart SQLite: таблицы, инкрементальная запись, миграция из SharedPreferences
    health_source.dart         интерфейс HealthDataSource + FakeHealthSource
    health_connect_source.dart единственный файл с кодом плагина `health`
    change_set.dart            изменения журналов с последнего сохранения (точечная запись)
    sqlcipher_opener.dart      единственный файл, открывающий базу через `sqflite_sqlcipher`
    default_data.dart          стартовые данные
  security/                    блокировка (AppLock), биометрия, шифрование базы (DbEncryptionManager), шифрование копий,
                               хранилище ключей, SecurityService; плагины — только в *_authenticator / secure_key_store / screen_security
  state/app_controller.dart    AppController (ChangeNotifier): вся бизнес-логика
  ui/
    app_shell.dart             оболочка: навигация, баннер хранилища, жизненный цикл
    screens/                   hub, gym, graph, mind, wealth, journal, finance, settings, onboarding
    widgets/                   body_map_card, health_card, comparison_card, goals_ui, form_dialog,
                               log_set_dialog, backup_actions, health_actions, confirm_dialog, toast
    painters/                  chart_painters, body_painter, graph_painter, anatomy_geometry
test/                          юнит-тесты логики и хранилищ + ui_smoke_test (виджеты, знакомство, настройки)
docs/HEALTH_SETUP.md           настройка Health Connect на Android
docs/SECURITY_SETUP.md         настройка и модель угроз: блокировка, шифрование базы и копий
```

Запуск: `flutter pub get && flutter analyze && flutter test && flutter run`

## Правила
- UI не меняет данные напрямую — только методы `AppController`.
- Экран = файл в `ui/screens/`; переиспользуемый блок = файл в `ui/widgets/`; логика без Flutter → `core/`.
- Платформенный код (плагины) — только за интерфейсом (`AppRepository`, `HealthDataSource`).
- Смена формата JSON → поднять `kSchemaVersion`; смена SQL-таблиц → поднять `kDbVersion` и добавить шаг в `_onUpgrade`.

## Хранилище (SQLite, `sqflite`)
Файл `life_os.db`. Таблицы: `kv` (скаляры и недельные истории), `docs` (мышцы, цели, достижения, зарплата,
узлы и связи графа, правила повторов, лимиты), `workout_sets` и `money_tx` (журналы, индексы по времени и категории).
- **Запись инкрементальная на двух уровнях.**
  - Журналы пишутся строго по `ChangeSet`: контроллер отмечает каждую вставку, правку и удаление подхода или операции
    (в том числе вытеснение по пределу и создание повторяющихся операций), репозиторий применяет только это — без обхода
    и сериализации всех записей (`AppData.toJson(includeLogs: false)`).
  - Малые данные (скаляры, мышцы, цели, граф…) сравниваются с отпечатками записанного состояния; пишутся только изменившиеся строки.
  - Если перечень изменений неизвестен (импорт, сброс, миграция, свежая установка, ошибка записи) — журналы переписываются целиком (`full`).
  - Сохранения выстроены в очередь; при ошибке следующая запись выполняется целиком.
- **Страховка**: `storage_sync_test.dart` прогоняет сценарии через контроллер, сохраняет и перезагружает из SQLite и сверяет
  состояние. Любая новая мутация журнала **обязана** попасть в `_pending` контроллера — иначе этот тест упадёт.
- **Миграция**: при первом запуске данные из SharedPreferences (JSON-блоб v3 и старые ключи v2) переезжают
  в SQLite; старые ключи не удаляются (можно откатиться на прежнюю версию).
- **Безопасность**: если базу не удалось открыть/прочитать, схема новее приложения или прежнее хранилище недоступно —
  контроллер переходит в режим «только чтение» (красный баннер), ничего не перезаписывая.
- **Замеры**: загрузка и крупные сохранения пишут время в диагностический журнал (Настройки → «Журнал диагностики»).
- Журнал и операции пока целиком загружаются в память; предел 50 000 записей каждого (`kMaxWorkoutSets`, `kMaxTransactions`).
  Ленивая загрузка по диапазону дат не делалась: она требует переработки статистики (рекорды, прогрессия, остатки) и
  оправдана только если замеры на устройстве покажут медленный запуск.
- Тесты репозитория используют `sqflite_common_ffi` и системную библиотеку sqlite3.

## Функциональность
- **Журнал тренировок**: история подходов, прогрессия 1RM, объём (без упражнений, шаблонов и таймера).
- **Цели**: сроки, правка, чекпоинты, в том числе автоматические по метрикам (1RM, капитал, доход).
- **Финансы**: операции по категориям, лимиты, повторяющиеся операции (создание, правка, удаление правил), правка операций, связь с чистым капиталом.
- **Здоровье**: Health Connect (шаги и активные калории), белок вручную.
- **Граф**: зум и панорама, правка узлов, типы и сила связей, анализ влияния.
- **Резервная копия**: экспорт/импорт JSON на HUB.

## Настройки и знакомство
- **Знакомство** (`onboarding_screen.dart`): имя → цели дня (шаги, белок) → деньги (по желанию) → Health Connect и способ старта
  («чистый старт» или «примеры данных»). Показывается при первой установке и по кнопке в настройках; данные не удаляет.
- **Новая установка начинается с чистого листа** (`AppData.blank`): нули, пустые журналы, цели и операции, граф только из «живых» узлов.
  Демо-данные (`AppData.defaults`) остались для примеров и тестов. Контроллер получает фабрику стартовых данных (`initialData`).
- **Существующие данные**: если в сохранении нет поля `onboardingDone` — знакомство не показывается, имя остаётся прежним.
- **Настройки** (`settings_screen.dart`): имя, цели дня, Health Connect, экспорт/импорт копии, примеры данных (с подтверждением),
  полный сброс (нужно ввести «СБРОС»), повторное знакомство, журнал диагностики (копируется в буфер обмена).
  Имя, цели дня и подключение Health Connect при сбросе сохраняются.

## Безопасность
Подробно и с настройкой Android — `docs/SECURITY_SETUP.md`.
- **Блокировка** биометрией или PIN устройства (запуск, возврат из фона, настраиваемая задержка), шторка вместо содержимого
  в списке недавних, защита от скриншотов (Android, нужен нативный канал).
- **Шифрование базы** (SQLCipher, ключ в Keystore/Keychain): включается и выключается в Настройках; миграция копированием с проверкой
  и откатом, доводка после прерывания (`recover()`), сброс хранилища при утерянном ключе.
- **Резервные копии с паролем** (PBKDF2 → AES-256-GCM); обычная копия остаётся доступной и помечена как незашифрованная.
- Настройки защиты лежат в SharedPreferences (привязаны к устройству), ключ — в защищённом хранилище, ничего не уходит в сеть.
