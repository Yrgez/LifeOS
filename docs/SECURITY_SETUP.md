# Безопасность: настройка и модель угроз

Что защищает приложение (всё включается в **Настройки → Безопасность / Данные**):

| Механизм | От чего защищает | Чего НЕ делает |
|---|---|---|
| Блокировка (биометрия или PIN устройства) | Посторонний, взявший разблокированный телефон или открытое приложение | Не шифрует данные; не спасает при физическом доступе к файлам на рутованном устройстве |
| Шторка / защита от скриншотов | Миниатюра в списке недавних, скриншоты и запись экрана (Android) | Не мешает фотографировать экран камерой |
| Шифрование базы (SQLCipher) | Извлечение файла базы с устройства (root, физический доступ, бэкап файлов) | Не защищает от того, у кого есть доступ к приложению в разблокированном состоянии; ключ хранится в Keystore устройства, а не вводится пользователем |
| Шифрование резервных копий (пароль) | Чтение копии в буфере обмена, в мессенджере, в файле | Пароль восстановить нельзя; обычный экспорт остаётся незашифрованным |

> Всё платформенное изолировано: `local_auth_authenticator.dart`, `secure_key_store.dart`, `sqlcipher_opener.dart`,
> `screen_security.dart`. Если API плагинов изменится — правятся только эти файлы.
> Шаги ниже собраны по документации плагинов (`local_auth` ^2.3, `sqflite_sqlcipher` ^3.4, `flutter_secure_storage` ^9.2);
> сверьте их с README установленных версий.

## Android

### 1. `android/app/build.gradle(.kts)`
`minSdk` — не ниже **26** (уже нужно для Health Connect).

### 2. `MainActivity.kt` — `FlutterFragmentActivity` + канал защиты экрана
```kotlin
package com.example.life_os

import android.view.WindowManager
import io.flutter.embedding.android.FlutterFragmentActivity
import io.flutter.embedding.engine.FlutterEngine
import io.flutter.plugin.common.MethodChannel

class MainActivity : FlutterFragmentActivity() {
    override fun configureFlutterEngine(flutterEngine: FlutterEngine) {
        super.configureFlutterEngine(flutterEngine)
        MethodChannel(flutterEngine.dartExecutor.binaryMessenger, "life_os/screen_security")
            .setMethodCallHandler { call, result ->
                if (call.method == "setSecure") {
                    val secure = call.arguments as? Boolean ?: false
                    if (secure) {
                        window.setFlags(WindowManager.LayoutParams.FLAG_SECURE, WindowManager.LayoutParams.FLAG_SECURE)
                    } else {
                        window.clearFlags(WindowManager.LayoutParams.FLAG_SECURE)
                    }
                    result.success(null)
                } else {
                    result.notImplemented()
                }
            }
    }
}
```
Без этого куска переключатель «Скрывать содержимое» всё равно работает в части шторки в списке недавних,
а защита от скриншотов тихо недоступна (запись в журнале диагностики).

### 3. `AndroidManifest.xml`
```xml
<uses-permission android:name="android.permission.USE_BIOMETRIC"/>
```
В `<application>` отключите автоматическое резервное копирование файлов — **это важно при шифровании базы**:
```xml
<application ... android:allowBackup="false" android:fullBackupContent="false">
```
Иначе Android может скопировать зашифрованный файл базы в облако и восстановить его на другом устройстве,
где ключа из Keystore нет, — данные станут нечитаемыми. Переносите данные через экспорт копии (лучше зашифрованной).

### 4. Тема для системного окна биометрии
По README `local_auth` для Android в `res/values/styles.xml` и `res/values-night/styles.xml`
родитель `LaunchTheme` и `NormalTheme` должен быть из семейства `Theme.AppCompat`:
```xml
<style name="LaunchTheme" parent="Theme.AppCompat.DayNight">
<style name="NormalTheme" parent="Theme.AppCompat.DayNight">
```

### 5. ProGuard / R8 (обязательно для release-сборки с SQLCipher)
Файл `android/app/proguard-rules.pro`:
```
-keep class net.sqlcipher.** { *; }
```
и подключите его в `buildTypes.release` (`proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")`).

## Как работает шифрование базы
- Ключ — 32 случайных байта (hex), хранится в Android Keystore / iOS Keychain (`flutter_secure_storage`). Пока ключ есть — база считается зашифрованной.
- Включение и выключение — **миграция копированием**: новая база создаётся рядом, копируется построчно, сверяется по числу строк во всех
  таблицах, подменяет исходную, снова проверяется; только после этого старый файл затирается и удаляется.
  Исходная база не меняется до успешной проверки; при любом сбое она возвращается на место.
- Если процесс прервали посреди миграции (питание, убитое приложение), при следующем запуске `recover()` доводит миграцию
  или откатывает её.
- Затирание удалённых файлов — best-effort: на флеш-памяти с журналируемой файловой системой физическое стирание не гарантируется.
- Если ключ утерян (очистка данных приложения, сбой Keystore, перенос на другое устройство), базу открыть нельзя:
  приложение запускается в режиме «только чтение», в Настройках появляется раздел «Хранилище недоступно» со сбросом
  (удаляет базу и ключ; восстановить данные можно только из резервной копии).

## Блокировка приложения
- При запуске и при возврате из фона (через выбранное время) показывается экран блокировки и системный запрос биометрии;
  допускается PIN/пароль/графический ключ устройства (`biometricOnly: false`).
- Включение и выключение блокировки требуют подтверждения личности.
- Если защита экрана на устройстве снята, блокировку нечем обеспечить: приложение открывается, блокировка отключается
  (иначе пользователь потерял бы доступ к своим данным).
- Настройки защиты хранятся в SharedPreferences, а не в базе: они относятся к устройству и не переезжают в резервной копии.

## Резервные копии с паролем
PBKDF2-HMAC-SHA256 (150 000 итераций) → AES-256-GCM, формат — JSON (`format: lifeos-backup`). Заголовок (формат, версия, число итераций)
аутентифицируется; число итераций хранится в копии, поэтому его можно повышать без потери совместимости.
Минимальная длина пароля — 8 символов. Обычный экспорт остаётся доступным и явно помечен как незашифрованный.
Буфер обмена на старых версиях Android доступен другим приложениям — предпочитайте шифрованную копию.

## Проверка на устройстве
1. Включить блокировку → свернуть приложение → вернуться: запрос биометрии; отмена оставляет экран блокировки.
2. «Скрывать содержимое»: в списке недавних приложений должна быть шторка, скриншот должен блокироваться.
3. Экспорт с паролем → импорт с неверным и верным паролем.
4. Шифрование базы: включить → закрыть приложение смахиванием → открыть: данные на месте. Выключить → то же.
5. Пробное прерывание: включить шифрование и сразу убить приложение — при запуске данные должны быть целы.
6. Release-сборка: убедиться, что приложение открывается (ProGuard-правило для SQLCipher).
