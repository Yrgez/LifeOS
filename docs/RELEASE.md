# Сборка, подпись и установка (Android)

Android-проект хранится в репозитории (`android/`). Всё, что раньше нужно было делать руками по
[`HEALTH_SETUP.md`](HEALTH_SETUP.md) и [`SECURITY_SETUP.md`](SECURITY_SETUP.md), уже в нём:

| Что | Где |
|---|---|
| Идентификатор приложения `io.github.yrgez.lifeos` | `android/app/build.gradle.kts` |
| `minSdk 26` (Health Connect), `compileSdk 36` для приложения и плагинов | `android/app/build.gradle.kts`, `android/build.gradle.kts` |
| Разрешения Health Connect, биометрии; **разрешения INTERNET нет** (удаляется, даже если его запросит плагин) | `android/app/src/main/AndroidManifest.xml` |
| Запрет системной копии и переноса файлов (зашифрованная база без ключа устройства нечитаема) | `AndroidManifest.xml`, `res/xml/data_extraction_rules.xml` |
| `FlutterFragmentActivity` и защита от скриншотов | `MainActivity.kt` |
| Тема AppCompat для окна биометрии, чёрный экран запуска | `res/values/styles.xml`, `res/drawable*/launch_background.xml` |
| Правило R8 для SQLCipher | `android/app/proguard-rules.pro` |
| Движок отрисовки Skia вместо Impeller (Impeller портит текст на Galaxy S10, Mali-G76) | `AndroidManifest.xml` |
| Подпись release-сборки | `android/app/build.gradle.kts` (ключ — из `android/key.properties` или секретов CI) |

`test/android_project_test.dart` проверяет эти настройки, CI — собранный APK
(идентификатор, номер сборки, разрешения, подпись).

## Почему нужен свой ключ подписи

Android ставит обновление поверх установленного приложения, только если оба APK подписаны **одним ключом**.
Без своего ключа каждая сборка CI подписывалась новым отладочным ключом: обновить приложение было нельзя,
только удалить и поставить заново — **а удаление стирает все данные**.

Ключ создаётся один раз и хранится всегда. **Потеряли ключ — обновлять приложение больше нельзя:**
только перенос данных копией в приложение с новым ключом. Сохраните файл ключа и пароли в менеджере паролей
или другом надёжном месте, отдельно от телефона.

## 1. Создать ключ (один раз, на своём компьютере)

Нужна утилита `keytool` — она есть в любой Java (JDK) и в Android Studio
(`<Android Studio>/jbr/bin/keytool`).

```
keytool -genkeypair -v -keystore lifeos-release.jks -alias lifeos -keyalg RSA -keysize 4096 -validity 36500
```

Утилита спросит пароль хранилища и имя (можно указать только имя). Пароль ключа — тот же.
Файл `lifeos-release.jks` **не кладите в репозиторий** (`.gitignore` его не пропустит).

## 2. Секреты репозитория для CI

GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret:

| Секрет | Значение |
|---|---|
| `LIFEOS_KEYSTORE_BASE64` | файл ключа в base64: `base64 -w0 lifeos-release.jks` (Linux), `base64 -i lifeos-release.jks` (macOS), `[Convert]::ToBase64String([IO.File]::ReadAllBytes("lifeos-release.jks"))` (PowerShell) |
| `LIFEOS_KEYSTORE_PASSWORD` | пароль хранилища |
| `LIFEOS_KEY_ALIAS` | `lifeos` |
| `LIFEOS_KEY_PASSWORD` | пароль ключа (тот же) |

После этого каждая сборка CI подписана вашим ключом. В сводке сборки виден отпечаток сертификата
(`certificate SHA-256 digest`) — у всех ваших сборок он одинаковый. Без секретов CI собирает APK
с отладочной подписью и пишет предупреждение: такой APK годится для проверки, но не для обновления.

## 3. Локальная сборка с ключом (необязательно)

Файл `android/key.properties` (в `.gitignore`):
```
storeFile=/полный/путь/lifeos-release.jks
storePassword=…
keyAlias=lifeos
keyPassword=…
```
и `flutter build apk --release`.

## Версия Flutter и движок отрисовки

CI собирает **закреплённой** версией Flutter (`flutter-version` в `.github/workflows/*.yml`, сейчас 3.50.0).
Причина: приложение отключает новый движок отрисовки Impeller (`io.flutter.embedding.android.EnableImpeller=false`
в манифесте) — на Galaxy S10 (Exynos, Mali-G76) он при первом показе экрана рисует в тексте чужие буквы и штрихи.
Flutter предупреждает, что этот переключатель уберут в одной из следующих версий. Перед обновлением Flutter:
проверить, что переключатель ещё действует (в журнале запуска нет Impeller), и пройти по вкладкам на Galaxy S10.

## Версия

- **Версия** (`1.0.0`) — в `pubspec.yaml`, меняется руками перед выпуском.
- **Номер сборки** — число коммитов в истории (`git rev-list --count HEAD`). Он только растёт, поэтому
  Android всегда принимает новую сборку как обновление.
- В приложении: **Настройки → О приложении → Версия** — «1.0.0 (сборка 412) · 4b9e89e» (последнее — коммит,
  из которого собрано). У локального запуска — «сборка для разработки».

## Выпуск версии

1. Поднять `version` в `pubspec.yaml` (например, `1.1.0+1` — число после `+` не важно, его заменит номер сборки),
   влить в `main`.
2. Поставить тег на этот коммит и отправить: `git tag v1.1.0 && git push origin v1.1.0`.
3. Workflow «Выпуск» (`.github/workflows/release.yml`) проверит, что тег совпадает с версией, прогонит тесты,
   соберёт подписанный APK и создаст выпуск на GitHub с APK, контрольной суммой и отпечатком подписи.
   Без ключа подписи выпуск не делается.

Промежуточные сборки — артефакты CI (Actions → запуск → Artifacts, хранятся 14 дней).

## Установка и обновление

- **Первая установка:** скачать APK на телефон, открыть, разрешить установку из этого источника.
- **Обновление:** так же открыть новый APK — «Обновить». Данные сохраняются. Если Android пишет
  «Приложение не установлено» или предлагает удалить старое — подписи разные (сборка без ключа или
  старый идентификатор). **Не удаляйте** приложение, пока не сделали копию.

## Переход со сборок `com.example.life_os`

До этой версии приложение называлось внутри `com.example.life_os` и подписывалось случайным ключом.
Для Android новая сборка — **другое приложение**: она встанет рядом, а данные не увидит. Перенос:

1. В старом приложении: **Настройки → Данные → Копия в буфер обмена** (лучше с паролем)
   или автокопия в папку (**Резервная копия → Сделать копию сейчас**).
2. Установить новый APK (появится второй значок LIFE OS).
3. В новом: **Настройки → Данные → Копия из буфера обмена** или **Резервная копия → Восстановить из файла**.
4. Проверить данные в новом приложении, затем удалить старое.

Снова включите в новом приложении: блокировку, шифрование базы, автокопию (папку и пароль копий),
напоминания и Health Connect — это настройки устройства, в копию данных они не входят.
